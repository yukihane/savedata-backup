# Process Monitor：実際の操作から保存先を調べる

調査日：2026-10-04。

[調査概要](README.md) / [Microsoft の公式説明](https://learn.microsoft.com/en-us/sysinternals/downloads/procmon)

## 何を観測できるか

Process Monitor は Windows のファイルシステム、レジストリ、プロセス・スレッドの操作を記録する汎用ツールです。プロセスの情報、各イベントの条件によるフィルター、プロセスツリー、ネイティブ形式での記録保存などが提供されています。[公式の機能説明](https://learn.microsoft.com/en-us/sysinternals/downloads/procmon#overview-of-process-monitor-capabilities)

ゲーム名やセーブ拡張子から候補を推測する方法とは異なり、実行中にアクセスした場所を観測できます。ただし、記録に「これはセーブデータ」という意味が付くわけではありません。書き込みの用途は別途判断します。

公開されたゲーム保存先検出アルゴリズムとして調べたものではなく、保存先を確認するための観測手段として公式文書を調べました。今回、アプリケーションの実行やゲームのトレース取得は行っていません。

確認時の公式ページは v4.11 で、動作対象として Windows 11 以上と Windows Server 2019 以上を記載しています。旧版の互換性は今回調べていません。[公式の動作対象](https://learn.microsoft.com/en-us/sysinternals/downloads/procmon#download)

## 保存先を調べるための手順案

以下は機能から組み立てた調査手順です。実施済みの検証結果ではありません。

1. ゲームを起動し、実際に動くプロセスを特定する。ランチャーの場合は、プロセスツリーでゲーム本体や子プロセスも確認する。
2. 対象プロセスのファイル・レジストリ操作を記録する。最初から保存先や拡張子で絞り込みすぎない。
3. セーブせずに少し操作した時間帯と、セーブを実行した時間帯を記録する。
4. セーブ時の書き込み、新しいファイル、一時ファイルの置き換えなどを比較する。ファイルを開いたというイベントだけで結論を出さない。
5. 別スロットへの保存、上書き、設定変更なども比べ、候補の用途を確認する。ゲーム終了時に保存する場合は終了まで記録する。
6. 観測記録と候補一覧を保存し、対象プロセス・操作内容・時間帯・書き込み先を残す。
7. 候補をバックアップし、ゲームを終了した状態で復元した後、ロードできることを確認する。元データを別に保全した検証環境で行う。

Windows の `CreateFile` は名前に反して既存ファイルを開く用途にも使われます。読み取り・書き込みの要求や、後続の操作も見る必要があります。[CreateFileW の公式仕様](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)

## 具体例：一時ファイルを経由する保存

たとえば、セーブ操作で次の順序の操作が観測されたとします。実際に取得したログではなく、確認すべき処理の例です。

```text
slot1.tmp を作成する
slot1.tmp にデータを書き込む
slot1.tmp を slot1.dat に置き換える
game.log に操作記録を書き込む
```

書き込まれたファイルだけを拾うと、一時ファイルやログも対象になります。最終的な `slot1.dat` と同じフォルダーの他スロット・共通データも確認し、復元時に必要な範囲を決める必要があります。

## 見落とし・誤認の要因

以下は観測方式からの考察です。

- セーブしていない機能や、まだ作っていないスロットの保存先は記録に現れない。
- オートセーブ、終了時の保存、子プロセスの操作は、記録する時間帯や対象を誤ると落ちる。
- ログ・設定・キャッシュも書き込まれるため、書き込みがあったことだけでは用途が決まらない。
- レジストリにも保存される場合は、ファイルのバックアップだけでは足りない。
- 保存先が複数ある場合は、1つの書き込み先の発見だけでは完全性を確認できない。
- 観測にはゲームの起動と操作が必要なので、遊んだゲームを思い出さずに候補を一括収集する用途には追加の手間がある。

## 後で検証したいこと

- 起動時・通常操作・セーブ時・終了時のイベントを分けて比較する。
- 一時ファイルからの置き換え、複数保存先、子プロセス、レジストリ保存を含むゲームで確認する。
- 候補の発見だけでなく、バックアップ・復元後のロードに必要な範囲を記録する。
- ゲームごとの操作時間と、ログから候補を判断する手間を測る。

推測方式の検出結果を調べる際にも、実際の書き込みの記録は参考になります。ただし、観測された操作と復元時に必要なデータの両方で確認する必要があります。
