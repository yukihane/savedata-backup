# セーブデータ保存先探索の先行事例調査

調査日：2026-10-04

ゲームごとの保存先情報が登録されていない小規模ゲームについて、既存ツールがどの情報を使い、どのように保存先を探すのかを調べた記録です。調査の出発点は [NOTE.md](../NOTE.md) です。

## 調査対象と確認方法

| 対象 | 確認方法・対象版 | 詳細 |
| --- | --- | --- |
| SaveState | 公式文書と、clone したソース。コミット `3b550e0dc38c001c42931cf9f476b4d8194420b1` | [SaveState の仕組み](savestate.md) |
| OpenSave | 公式文書と、clone したソース・テストコード。コミット `346d9bda0749fb57b48fd266f13e535af80f0285` | [OpenSave の仕組み](opensave.md) |
| Process Monitor | Microsoft の公式文書。掲載版 v4.11 | [実行時の操作から調べる方法](process-monitor.md) |

詳しいコード調査は Windows の保存先探索を中心に行いました。SaveState と OpenSave は一時フォルダーに clone して読み取りました。アプリケーションや先行事例のテストは実行しておらず、実際の同人ゲームでの検出・バックアップ・復元精度は未検証です。

各文書では、公開ソースや公式文書で確認した事実、そこからの考察、今後の検証項目を分けています。具体例に登場するゲーム名とパスは、仕組みを説明するための架空の例です。

## 主な結論

先行事例には、次の異なる方法があります。

| 方法 | 主な入力 | 候補の作り方 | 個別の保存先登録がないゲームへの見込み |
| --- | --- | --- | --- |
| SaveState の推測 | ゲーム名、インストール先、実行ファイル名 | よく使われる保存領域を探し、名前・拡張子・構造で候補を採点 | 名前や構造に手掛かりがあれば候補になる |
| OpenSave の慣例探索 | ディスク上のフォルダー構造 | Unity／Unreal などの既知の配置や、保存先らしいフォルダーを列挙 | 共通の配置に従う保存先なら候補になる |
| 保存先データベース | ゲームごとのパス定義 | 定義の変数やパターンを展開し、存在する保存先を探す | 定義がなければ別の探索手段や手動設定が必要 |
| Process Monitor の観測 | 実行中のファイル・レジストリ操作 | ゲームでセーブした時間帯の書き込み先を確認 | 実際にゲームを起動して操作できれば調査できる |

表の前半2方式の根拠は各詳細文書、パス定義の仕様は [Ludusavi Manifest](https://github.com/mtkennerly/ludusavi-manifest#format)、観測の機能は [Process Monitor の公式説明](https://learn.microsoft.com/en-us/sysinternals/downloads/procmon) にあります。「見込み」は各方法からの考察であり、ゲーム群を使った実測結果ではありません。

今回確認した SaveState と OpenSave の保存先探索処理は、exe 内部から保存先の文字列を抽出する方式ではありません。SaveState が使う実行ファイルの**名前**と、バイナリ**内部の文字列**は異なる情報です。これらの方法の採用や組み合わせは、別途検討する必要があります。

また、候補の存在、セーブらしい拡張子、実際の書き込みのいずれも、それだけでは「必要なセーブデータをすべて含む」という証明になりません。複数の保存先、設定・ログの混入、未操作のセーブ機能を含めて確認する必要があります。

## その他の関連ツール

以下は公式説明を確認した範囲の比較です。今回、保存先探索コードの詳細調査は行っていません。

| ツール | 確認できた方式・用途 | 未登録ゲームについての論点 |
| --- | --- | --- |
| [Ludusavi](https://github.com/mtkennerly/ludusavi/blob/master/docs/help/custom-games.md) | 保存先マニフェストを利用し、独自のゲーム定義も追加できる。[マニフェスト](https://github.com/mtkennerly/ludusavi-manifest) は主に PCGamingWiki 由来のパス情報を持つ | 独自定義は可能だが、保存先を調べて登録する作業が残る |
| [GameSave Manager](https://www.gamesave-manager.com/) | 対応ゲームのデータベースを持つバックアップツール | 今回の確認では、未登録ゲームを一般的な推測で探索する仕組みまでは確認できていない |
| [Game Backup Monitor](https://mikemaximus.github.io/gbm-web/manual.html) | ゲーム設定を取り込み、または手動登録し、ゲーム終了後にバックアップする。Ludusavi マニフェストの取り込みにも対応 | 実行・終了の監視と、保存先の推測は別の機能。未知の書き込み先を自動発見する説明とは区別する |
| [Game Save Manager（dyang886）](https://github.com/dyang886/Game-Save-Manager#smart-detection-engine) | インストール先と既知の保存先を探索。未インストールのゲームが残したデータも探し、独自設定も追加できる | ゲームを忘れていても既知の保存先は見つかり得る。保存先情報自体が未登録の場合の手間が比較対象になる |

「ゲームを覚えていなくても探せる」と「保存先情報が未登録でも探せる」は別の能力です。データベース方式でも、対応する保存先が残っていれば、利用者が忘れているゲームを発見できる場合があります。

## 後続の検証で比較したいこと

今回の調査から、採用判断の前に次を測るとよさそうです。これは検証案であり、実施済みの結果ではありません。

- 同じ小規模ゲーム群を使い、手動調査・実行時の観測・ロード確認で実際の保存先を記録する。
- 日本語タイトル、汎用的な `Game.exe`、タイトルと異なる内部名、インストール先の移動を含める。
- ゲーム横の保存先、AppData、Documents、複数アカウント、複数保存先を比較する。
- 独自拡張子、JSON、設定と進行状況を同じファイルに持つゲーム、レジストリへの保存を含める。
- 見つかった保存先、見落とし、余分に含まれたデータ量、手動操作の数、探索時間を記録する。
- アクセス不可や探索制限に達した場合を、「候補なし」と区別できるか確認する。
- バックアップから戻したデータをゲームでロードし、保存先の発見とバックアップの完全性を別々に評価する。

本調査では先行事例の仕組みと検証論点を記録しています。本プログラムのコードレビューや、機能追加・方式選定は対象に含めていません。
